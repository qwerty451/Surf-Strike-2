# Gamemodes

Every map belongs to one gamemode: its `MapDef.kind` (the field keeps its old name). There are six modes:

| Mode | Family | Rules | Default cvars | Min players | Scoreboard (plus the totals) |
| --- | --- | --- | --- | --- | --- |
| `surf` | race | Timer, start/end zones, stages, PBs, leaderboard ([gameplay.md](gameplay.md)) | `SURF_CVARS` | 1 | Rank, PB, Status, Ping |
| `bhop` | race | Same as surf | `BHOP_CVARS` | 1 | Rank, PB, Status, Ping |
| `tag` | tag | Rounds of tag, see [Tag](#tag) | `TAG_CVARS` | 2 | Time not IT, Status, Ping |
| `zombies` ("Zombie Run") | coop | Co-op escape with weapons against AI zombies, see [Zombie Run](#zombies) | `ZOMBIES_CVARS` | 1 | Kills, Turned, Status, Ping |
| `infected` | infected | Infected with throwing knives, see [Infected](#infected) | `INFECTED_CVARS` | 2 | Score, Kills, Streak, Deaths, Status, Ping |
| `hns` | hns | Hide and seek with knives; found hiders become seekers, see [Hide and seek](#hide-and-seek) | `HNS_CVARS` | 2 | Role, Finds, Survived, Ping |

The map rotation, vote, `!rtv`, chat, spectating and lobby are the same in every mode. The rotation mixes maps of all modes, so a vote can move the lobby from a surf map to a tag map.

## Framework

```
packages/shared/src/modes/
  index.ts   GameModeId, GAME_MODES registry, modeOf(map), mapCvars(map), TAG_CVARS
  score.ts   ModeScoreDef per mode: scoreboard columns, score panel, order, marks; buildScorePanel
  tag.ts     TagGame: pure tag rules with an injected clock, plus tagTouch, randomSpawn, hullInBox
  hns.ts     HnsGame: pure hide and seek rules (clock-injected), knifeHit, hnsSpawns, HNS_* constants
apps/server/src/modes/
  types.ts   ServerMode interface, ModeHost, ModePlayer
  race.ts    RaceMode: RunValidator per player, PB/leaderboard, !top/!pb, race scoreboard, coins
  tag.ts     TagMode: runs TagGame on the latest state packets, chat announcements, modeState
  hns.ts     HnsMode: runs HnsGame, knife messages, event routing, announcements, speed-cap check
  index.ts   createServerMode(host): picks the module by GAME_MODES[kind].family
apps/web/src/lib/game/modes/
  types.ts   ClientMode interface, ClientModeHost
  race.ts    RaceMode: RunTracker, splits, solo PBs, ghosts
  tag.ts     TagMode: tag state and HUD view
  zombies.ts, infected.ts, hns.ts   adapters around ZombiesClient, InfectedClient, HnsClient
  index.ts   createClientMode(host), startSpawn(map): pick the module by GAME_MODES[kind].family
```

- **Registry.** `GAME_MODES[id]` gives a mode's `label`, `family` (`race` or its own), `cvars` profile, `minPlayers` and `score` (see [Score display](#score-display)). `mapCvars(map)` is the mode profile plus the map's `cvars` overrides; the server sends it in `welcome` and `mapChange`.
- **Server.** The lobby has no mode logic. It owns one `ServerMode` per map and replaces it on map change. It forwards these calls: `join` (after `welcome`/`mapChange`), `leave`, `spectate`, `state` (each state packet), `zone`, `command` (`!top`, `!pb`), `scoreRows`, `records` and `tick`. `tick` runs at `MODE_TICK_HZ` (32 Hz).
- **Client.** `game.ts` has no mode branches either (records, PBs and the stage count of race maps are still there). It owns one `ClientMode` per map (`modes/types.ts`) and replaces it on a map change, and on a disconnect unless the mode has `offline()` (a race run goes on, tag goes back to free roam). It asks the mode for the physics cvars of a tick (or none: no movement), the state packet's status, the camera effects, the looks of remote players and the solo row; it forwards buttons, number keys, `R`, `!r`, the mode's server messages and binary frames; `tick` runs after the movement of every tick and `frame` once per frame, where the mode publishes its HUD view. Race modes run `RunTracker` every tick. In tag, hide and seek and infected without a round, teleport zones respawn the player at a spawn of the mode. The race HUD (timer, splits) shows in race modes only. `hud.gameMode`, `hud.modeFamily` and the mode's own HUD field drive the UI. The scoreboard and the score panel render `GAME_MODES[mode].score`.
- **Protocol.** These changes are additive. `welcome` and `mapChange` carry `mode`. Non-race modes send `modeState` messages; race modes never do. `ScoreRow` has optional mode fields (`score`, `it`, `kills`, `deaths`) and optional account totals (`pointsTotal`, `playtimeSecs`, `coins`), which the lobby adds to every mode's rows. `Status` has new `Tagger` and `Runner` values.

### Score display

`packages/shared/src/modes/score.ts` defines what each mode shows in the Tab scoreboard ([gameplay.md](gameplay.md#tab-scoreboard)) and in the always-on score panel ([ui.md](ui.md#score-panel)). `GAME_MODES[id].score` is the mode's `ModeScoreDef`; the Svelte components only render it and have no mode branches.

| Field | Meaning |
| --- | --- |
| `columns` | Ordered `ScoreMetric`s: `id`, `label`, `short` (panel header), `num`, `width` (em, scoreboard), `text(row, ctx)`. `panel: true` also makes it a column of the panel's standing; `minor: true` drops it first in narrow windows. `scoreboardColumns(def)` appends Coins and Total playtime (`TOTAL_COLUMNS`) in every mode |
| `compare(a, b)` | Row order, best first (scoreboard and standing) |
| `mark(row)` | Optional role marker: `text` (scoreboard chip), `short` (panel chip), `tone` (row colour) |
| `panel.list` | `records` (the map's leaderboard: surf, bhop) or `standing` (the players in the current game) |
| `panel.title`, `panel.subtitle(input)` | Default title: the mode's label. The standing modes show "Round 3" |
| `panel.maxRows` | Row cap, your own row included (6 records, 8 players) |
| `panel.summary` | Lines under the list: `{ id, line(input) }`, where `line` returns `{ label, text, note?, tone? }` or null |

- **A new per-player metric** is one entry in the mode's `columns`. `text` gets the `ScoreRow` and `ctx.state`, the latest `modeState` of the mode (the infected streak is read from it, so it needs no row field). **A new game-wide or personal line** is one entry in `panel.summary`; its input also has the race records (`records.top`, PB, record).
- Values can be missing (older server, offline, no state yet): `text` and `line` must fall back and never throw.
- A new `tone` also needs a colour in `ScorePanel.svelte` and `Scoreboard.svelte`. If a mode's HUD uses the right edge of the screen, add its space to `AREAS` in `apps/web/src/lib/ui/score-panel.ts`.

### Adding a mode

1. Add the id to `GameModeId` and an entry to `GAME_MODES` (new `family` if it is not a race), with its `ModeScoreDef` in `score.ts`.
2. Put its pure rules in `packages/shared/src/modes/<mode>.ts`, with vitest tests on a fake clock.
3. Add `apps/server/src/modes/<mode>.ts` implementing `ServerMode`, and a case in `createServerMode`.
4. Add a `ModeState` variant to `protocol.ts` (keep the `{ type: 'modeState', mode }` shape).
5. Client: add `apps/web/src/lib/game/modes/<mode>.ts` implementing `ClientMode` and its entry in `modes/index.ts`, HUD fields in `contract.ts` and a HUD component. A new server message type also goes into `ModeServerMessage`, a new mode command into `ModeCommand`; `game.ts` only forwards them.
6. Give its maps `kind: '<mode>'`, and add map checks in `maps/maps.test.ts`.

## Tag

Server-authoritative. The shared `TagGame` class runs on the server, using the latest state packet of every player who is not spectating.

- **Phases.** `waiting` is free roam with nobody IT, while fewer than 2 players are active. `countdown` lasts 5 s, then a round starts. `playing` lasts 3:00. After a round, the next `countdown` starts. If players drop below 2 at any point, the mode goes back to `waiting`, and a running round is cancelled.
- **IT.** At round start, one random active player is IT. With 8 or more players, two players are IT. If an IT leaves mid-round, a random runner becomes IT.
- **Tagging.** An IT tags a runner whose hull it touches: the horizontal distance between origins is ≤ 40 units (`TAG_RANGE`; hulls are 32 wide), and the hulls overlap vertically (72 tall, 54 ducked). The server checks this at 32 Hz. If several runners touch, the closest one is tagged. The tagged player becomes IT, and the tagger becomes a runner with 3 s of tag-back immunity. A player tagged in one check cannot tag in that same check. There is no freeze after a tag.
- **Score.** Your score is the number of seconds you were not IT this round. Late joiners start at 0 as runners. Scores reset at round start and stay visible during the countdown.
- **Round end.** Chat announces the top 3 (`Round 2 over! 1. Alice 151.2 s  2. ...`), and the next round starts after 5 s.
- **Coins.** Being chased, different runners tagged and the top three places pay coins ([economy.md](economy.md#tag)). `TagMode` runs a `HuntTracker` on the runners and ITs.
- **Messages.** `modeState { mode: 'tag', phase, round, timeLeft, it[], immune[], scores[] }` is sent on every change and at least once a second. `tagged { by, target }` is sent on each tag. Chat announces countdowns, round starts, tags and IT handovers.
- **Client.** The tag HUD shows an IT or RUNNER banner, the round time left, your score, who is IT and a short flash on tags. Remote IT players have a red tint and a red `IT · name` tag. `!r` / `!back` respawn at a random spawn, but not during a round. `!top` / `!pb` show your round score. Offline, or alone on the server, the HUD shows "Waiting for players — tag needs 2+" and you roam freely; there are no bots.
- **Physics.** `TAG_CVARS` is `BHOP_CVARS` (modern CS2 jump, autobhop) with `sv_airaccelerate 150`. This keeps chases readable, and the map's surf sections still work.
- **Maps.** A tag map has `kind: 'tag'`, `layout: 'open'`, at least 8 `spawns`, and only teleport zones, with one teleport zone under everything for fall-outs. There are no start, end, stage or checkpoint zones. See [maps.md](maps.md).

## Infected

Server-authoritative Infected. The shared `InfectedGame` class (`packages/shared/src/modes/infected/game.ts`) runs on the server; clients send `fire`, `reload`, `loadout` (weapon swap), `throwKnife`, `placeBeacon` and `callMoab`, and render predicted throwing knives and UAV pulses. The server checks every field of these messages in `apps/server/src/modes/infected-input.ts`; a malformed message is dropped whole.

- **Phases.** `waiting` (< 2 active players; see [Practice range](#practice-range)) → `grace` (12 s pre-infection spread-out) → `playing` (2:00 round clock, +20 s added on every infection) → `ended` (7 s round summary) → `grace`.
- **Patient Zero (Alpha).** At the end of `grace`, one random player becomes Patient Zero. Infected never have guns: Patient Zero gets claws + throwing knife right away, like everyone who turns later, and cannot switch weapons. The Patient Zero look and name last until the first infection. The picked player gets the same transition as a survivor who turns: a burst at the body and the avatar easing into the Patient Zero look.
- **Survivor classes.** Each round rotates the survivor primary through `INF_PRESETS` (labels in parentheses): `barrett` (`.50 cal rifle`) → `striker` (`Auto shotgun`) → LMG → SMG → sniper rifle. Every class has three slots, each with its own magazine and reserve. Swaps never reset ammo. A swap cancels a reload and draws the new weapon, which cannot fire for its `deployMs` (knife 200 ms, pistol 250, SMG 350, Auto shotgun 450, sniper 600, LMG and .50 cal rifle 650). The server enforces the draw with the fire tolerance (× 0.75). A trigger held through the draw fires when it ends; an earlier tap is dropped. Weapons the server hands out (spawn, role change) have no draw.
  - `[1]` the round primary, `[2]` the pistol (`INF_SECONDARY`, 12 + 36), `[3]` the knife. `4` (or `N`) calls an earned M.O.A.B.
  - **.50 cal rifle** (`barrett`): semi-auto anti-materiel rifle, one-hit kill, pierces 3, 10 + 20 rounds. Aiming looks through a 38° scope.
  - **Auto shotgun** (`striker`): semi-auto drum shotgun, 8 pellets in a 4° cone per trigger pull (1 damage each), 12 + 24 shells, 1400 u range. The server resolves every pellet and sends the other clients each pellet's direction and length in `shot.pellets`. Every client draws one cosmetic tracer per pellet.
  - **LMG**: 750 rpm, 100 + 100 rounds, slowest run speed.
  - **SMG**: ~920 rpm, 36 + 72 rounds, fastest run speed (245 u/s).
  - **Sniper rifle** (`sniper`): bolt action, one-hit kill, pierces 3, 5 + 15 rounds. Aiming looks through a 40° scope, which stays up while the bolt cycles.
  - Ammo is limited (`INF_AMMO`). Before Scavenger, an infected kill refills 40% of the primary's scavenger share.
- **Aim down sights (`Mouse2`).** Every gun aims; melee does not. An infected player holding a throwing knife (Patient Zero too) throws it with `Mouse2` instead. `Mouse2` is held by default; `cl_aimtoggle 1` (Settings › Mouse › "Toggle aim") makes it a toggle. A gun comes up to its sights in its aim time (`AIM` in `apps/web/src/lib/game/gunfeel.ts`): 200 ms for the pistol, SMG and Auto shotgun, 379 ms for the LMG, 400 ms for both rifles. The aimed FOV is the source weapon's magnification applied to the player's `fov`; the pistol has none, and the two rifles zoom to their scope's `zoomFov`, with the scope overlay taking over in the last 40% of the aim. The FOV itself moves only in the last 180 ms of the aim (`ZOOM_MS`; the whole aim for the 200 ms guns): the gun comes up first, then the view zooms. Aiming slows movement by the gun's factor (0.8 for the pistol and SMG, 0.4 for the others). Reloading pauses the aim and a swap restarts it from the hip; a held aim comes back by itself, a toggled one is switched off by a reload, a swap or a knife throw. Death, spectating, a respawn and the round end let go of it. While aimed, mouse sensitivity is scaled by `zoom_sensitivity_ratio` ([ui.md](ui.md#developer-console)).
- **Gun feel** (`apps/web/src/lib/game/gunfeel.ts`, client-side; the server never reads these values). The aim, recoil and spread values are calibrated on a published statistics sheet of a 2011 console shooter, converted to this game's field of view.
  - **View kick.** Every shot turns the camera off the point you aim at, and the shots follow the camera. Each shot gives pitch and yaw a random velocity within the gun's range (no pattern). Moving away, the view is slowed by the gun's centre speed; moving back, it is pulled by a sixteenth of it (`VIEW_KICK_RETURN`), so it peaks fast and drifts back. It stops exactly on the aim point and never goes more than 10° off on either axis (`VIEW_KICK_BOUND`). Yaw kicks also roll the camera by half the yaw velocity. A shot fired while the view is off-centre replaces its velocity; a kick that points back towards the aim point keeps a sixteenth of its strength. One shot moves the picture as far on screen as the source weapon's aimed shot. Hip fire, aimed fire and the scoped rifles have their own sets (`RECOIL`); a shot blends hip and aimed by the aim progress. Mouse movement is never undone.
  - **Gun kick.** The first-person gun also rotates about its grip with every shot (kicks add up and spring back) and pushes back briefly. From the hip this is only visual. Aimed through iron sights, a quarter of the gun kick (`AIM_GUN_KICK`) turns the shots too; through a scope the scoped view kick carries it all.
  - **Recoil is fixed.** No cvar, setting or console command scales or disables it, and `prefers-reduced-motion` does not either (`infected-kick.test.ts` pins this).
  - **Hip spread.** Each gun has a hip cone (`SPREAD`, half-angle): from its minimum at rest it grows with firing (bloom per shot, recovering after a short pause) and with movement (full at run speed), is at its maximum while airborne, and starts from a smaller pair when ducked on the ground. Steady Aim halves it. The cone shrinks with the aim progress: fully aimed there is no aim spread. The Auto shotgun's aim cone is 1°, and its 4° pellet cone (`pelletSpread`) stays while aimed.
  - **Knockback** on the local player is an impulse added to the velocity, capped at 300 u/s along the hit direction (`addKnockback`): a hit head-on takes speed away, and a hit from behind or stacked hits cannot launch anyone.
- **Specialist perks (kill streaks).** Infected killed in one survivor life build a streak; perks unlock at `INF_PERK_KILLS` and end with that life (a fall-out keeps them). Hardline is the base perk: the M.O.A.B. needs 24 kills instead of 25.
  - 1 kill **Sleight of Hand**: reloads take half as long (`INF_SLEIGHT_RELOAD_FACTOR`).
  - 3 kills **Scavenger Pro**: every kill refills a full scavenger share of the primary (reserve up to 1.5× its cap) and of the pistol.
  - 5 kills **Steady Aim**: half spread (the hip cone and shotgun pellets, `INF_STEADY_SPREAD_FACTOR`) and 12% more run speed (`INF_STEADY_SPEED_FACTOR`).
  - 7 kills **Specialist**: all perks plus 15% faster fire cadence (`INF_SPECIALIST_CADENCE_FACTOR`), 20% more knockback and `+250` score.
  - A `perk` event announces each unlock; the client predicts the reload, cadence, spread and speed factors and reconciles streak and perks from `modeState`.
- **M.O.A.B.** At a 24-kill streak (`INF_MOAB_KILLS`) the survivor gets a private `moabReady`. `N` (or `4`) sends `callMoab`; everyone sees `moabCall` and a 10 s countdown (`INF_MOAB_COUNTDOWN_SECS`, also in `modeState.moab`). On `moabDetonate` every living infected dies, the caller gets the kills and `+500`, and the survivors win the round. The countdown is dropped if the round ends first.
- **Combat & Respawns.** Claws and throwing knives are instant 1-hit infections, so survivors have no health bar. Infected have 5 HP (headshots instakill), suffer hit slows/knockback, and respawn after 3 s at the spawn farthest from living survivors with a fresh throwing knife. Late joiners during `playing` spawn as infected. Melee reach is measured to the nearest hit capsule, arms included: claws connect on the hands of a survivor aiming at them before they reach the chest (level: the hands end 18 units in front of the feet with the pistol, 13.5 with the knife and 22 to 23 with a long gun, the chest 7). Melee also needs a clear line from the eye to a point 40 units up the leaning body (30 ducked, on the line from the feet to the neck).
- **Hitboxes.** Bullets, claws, knife swings and the throwing knife test capsules on the joints of the drawn [character](characters.md) (`rayPlayer`, `meleePlayer`, `sweepPlayer` in `packages/shared/src/modes/zombies/hitbox.ts`). The server poses them from what it has: position, yaw, posture (infected and Patient Zero share one hunch), the held item (claws for every infected), and the motion (`PlayerBody` in `body-motion.ts`), which it steps from the velocity, ground flag, duck and view of the state packets with the animator's own eases. Both sides call the same formulas (`packages/shared/src/body-pose.ts`): torso and head pitch with the view and lean with the run, jumps and ducks blend as drawn, and the arms reach to the item with the animator's own numbers (`PLAYER_HOLDS`, `PLAYER_GRIPS`, `PLAYER_ELBOWS`). The velocity is clamped to what the mode allows (`INF_SPEED_LIMIT`, `sv_maxvelocity`); other clients draw it with the same clamp (`clampInfVelocity`).
  - **Standing still** it is 18 capsules: every point of the body is inside one or less than 0.4 units outside, and no capsule sticks out more than 3.9 units (`infected-hitbox.test.ts` samples the skinned meshes: a survivor with every item, infected and Patient Zero with claws, in every stance and pitch).
  - **On the move** (`infected-motion.test.ts`: walking to 340 u/s in eight directions, every survivor hold and the claws of infected, every pitch, ducked, in the air) torso, head and held arms are drawn at most 1.5 units outside. The gait phase is only known to the client that draws it, so the legs and arms that hold nothing are tested at places over their whole swing (with either leg in front in the air, and with the feet trailing a turn on the spot by up to 43°): every drawn point of a leg is less than 0.4 units outside, and no capsule is further than 3.9 (torso and arms 4) from anything drawn over a cycle. A shot between the legs of a runner hits where a leg passes.
  - **During a change** of motion the client draws 32 snapshots a second and the server's copy of them can differ for a moment. Measured at 60 frames a second: up to 4.1 units on the torso, 5.1 on the arms and 2.7 on the legs for the 0.2 s of a duck (6.6 and 7.9 at 30 frames a second), 2.0 on the legs of a flick on the spot, 2.8 on the claws of an infected that flicks its view around on the run, at most 1.5 otherwise.
  - **Not followed**, because only the drawing client knows it: the surf stance, the blend between two held items, recoil, reloads and swings. A client that did not see a backpedalling player turn into a strafe (off its screen) may draw the hips the other way around until the strafe ends: the legs are then up to 13 units off.
  - One size for every look: cosmetics never change a capsule, and the ponytail, talons, throwing knife and held item cannot be hit. An arm in front of the face takes a bullet as a body hit. The throwing knife adds its 10 unit radius.
- **Lag compensation.** A shot or swing is tested against the poses the shooter saw: `infRewindMs(ping)` = ping + `INTERP_DELAY_MS` (100) + half a snapshot interval (15.6) ms back, interpolated between history samples, at most `INF_HISTORY_MS` (400) and never before the target's last spawn or teleport. The pose history keeps the pitch, the held item and the motion (lean, duck, stride speed, jump), so a rewound shot meets the body the shooter saw. Throwing knives are server-simulated and hit the current poses. See [architecture.md](architecture.md#netcode).
- **Throwing knife (`Mouse2`).** One per life for infected. Server-simulated parabolic gravity arc (`1150 u/s`, gravity `650 u/s²`) that bounces once off walls/floors (bank shots stay lethal and award a bonus) before sticking on the next contact (or dropping cleanly to the floor if it hits high up on a wall or ceiling). Stuck knives stay in the world and can be retrieved by their owner walking over them. The `infect` event of a thrown knife (`method` `knife` or `bank`) carries `dx`, `dy`: the unit horizontal direction the knife travelled when it hit, after the bounce for a bank shot. A knife falling straight down uses thrower towards victim. Claw infections carry no direction.
- **Respawn beacon (`E`).** Infected players can plant a glowing beacon flare on the walkable ground below them, also in mid-air up to 256 u above it (`1.5 s` cooldown, max 1 active; re-planting replaces the previous beacon). Without flat, open ground below, a private chat line says so. Dying or falling out of the map while a beacon is active respawns you directly at your beacon (consuming it). Survivors can shoot or knife enemy beacons (1 hit) to smash them for `+50` score and deny the forward respawn.
- **Last Survivor UAV.** When 1 survivor remains against 2+ infected, a UAV sweep pulses their position every 5 s as a through-wall 3D beacon for infected.
- **Scoring.** Kill infected `+100`, infect survivor `+150` (`+50` throwing knife, `+50` bank shot), survive an infection `+25`, survive the round `+250`, smash a beacon `+50`, Specialist `+250`, M.O.A.B. `+500`.
- **Coins.** Kills, infections, surviving, the last survivor, Specialist, M.O.A.B., beacons and the infected win pay coins ([economy.md](economy.md#infected)), separate from this score.
- **Round summary.** The `end` event carries `stats`, one `InfRoundStat` per player present, in scoreboard order (score, kills as a survivor, infections, deaths, shots, hits, headshots, best streak, seconds survived, was Patient Zero), and `nextLoadout`, the next round's survivor primary. Shots count gun trigger pulls only while the round is played; hits and headshots count trigger pulls that hit at least one player. Stats reset at every grace period and follow a player through a leave and rejoin. The HUD shows them as a table ([ui.md](ui.md#infected-hud)).
- **Hit and kill feedback** (`render/infected-fx.ts`, `game/infected-feedback.ts`). A killed infected collapses and fades as the character it was, in its death pose, clothes and look (infected or Patient Zero), falling away from the killer; a M.O.A.B. drops every living infected where it stands, as a short wave. No blood. A survivor who turns gets a burst in the red of the infected eyes and eases into the infected colours over 450 ms (posture and claws switch at once, as the hit capsules do). Your hit flashes the victim white for 100 ms. Bullets leave sparks and a dust puff where they meet the map, for local and remote shots; the client traces the ray, so a shot that ended on a player leaves none. Corpses are pooled characters posed once, at the detail the avatar had. Caps: 32 corpses, 8 bursts, 64 impacts, 96 tracers.
- **Remote players** (`render/players.ts`, `render/character/`). Other players are [characters](characters.md) with their current weapon in their hands; swaps dip through the unarmed pose. Infected show talons and the throwing knife in the left claw. Head, torso, arms and weapon follow the view pitch. A remote shot shows recoil, a muzzle flash and a case at the gun, and its tracers start there, one per shotgun pellet; a swing slashes with the right arm. A remote reload shows for as long as it takes that player ([characters.md](characters.md#animation)); a sniper shot is followed by the bolt. Swaps reach the others with the mode state (up to 250 ms late), but one that ends a reload tells them at once.
- **Weapon models.** In first person the guns and the knife use textured 3D models (`apps/web/static/models/weapons/<id>-fp.glb`), loaded the first time a weapon is held; the code-built model (`render/viewmodels.ts`) shows until a file has loaded and stays if loading fails. Every gun is modelled by a Blender script (`tools/models/procedural/`); the knife is a generated model. The claws and the throwing knife are code-built only, and other players always hold the low-poly meshes of `render/character/held-models.ts`, in the layout and colours of the script-built guns. Fit data, including the sight line that aiming puts on the view axis, is in `render/weapon-assets.ts`; `tools/models/procedural/` rebuilds the guns from their scripts and `tools/models/build.sh` the knife from its raw image-to-3D model.
- **First-person gun animation.** The guns move on their own parts (`render/gun-rig.ts`) and the gloved hands go with them (`render/hands.ts`). `render/fp-clips.ts` holds the moves as pure data, `render/fp-anim.ts` plays them, and `ZombieRenderer.updateViewmodel` takes the rounds left so an empty gun looks empty.
  - **Shots.** The slide, bolt or charging handle goes back and returns within the fire interval (48 to 180 ms), the trigger and the trigger finger move, the LMG's belt goes on by one round along its way out of the box and into the feed. The pistol locks back on its last round and the LMG's belt runs out with the box. The sniper's right hand works its bolt after each shot (0.9 s, inside the fire interval, behind the scope too). A click on an empty chamber moves only the trigger.
  - **Reloads** last exactly the reload time. The gun turns its underside to the left hand; the old magazine (tube, box, drum) leaves along its well and the screen, the new one comes in and seats with a shove. An empty gun ends with its slide or charging handle; with a round left that part is left out and the time stays the same. The LMG's left hand takes the feed cover by its edge, opens it, changes box and belt and closes it, never faster than 2.1 m/s; the sniper opens its bolt first and closes it last. A hand on a knob, a handle or the slide holds it, thumb across from two fingers, all the way, and opens as it lets go. Magazine, bolt and cover move at the moments other players see (`render/character/reload.ts`). The middle of the screen stays clear.
  - **Cut short.** A cancelled reload is back at rest in 140 ms. A swap takes the gun down out of the picture as it was, in 130 ms, while the next one comes up. Death, infection and spectating hide it at once.
  - **Contact.** `fp-contact.test.ts` measures every clip on the shipped meshes: hands at most 0.10 model units into the gun on a named pose and 0.25 in a blend, a magazine 0.10 on its track and 0.25 off it (in the gun, and the gun in it), nothing through the near plane, no sleeve end in view. `hand-contact.test.ts` checks what each pose holds, with the part all along its travel.
- **Casings** (`render/casings.ts`). Brass by calibre, red shells for the shotgun, cases and links for the LMG; the sniper's case only as its bolt opens. Mine arc up and to the right inside the view, from the hip and aimed, clear of the crosshair; they start at the ejection port in the viewmodel scene for 110 ms and then are in the world, on the same pixel and as big; they take my velocity along, bounce on the map at most four times, lie for 5 s and shrink away. Other players' cases show within 700 units. At most 96 at once, oldest first out, one instanced mesh per kind; cleared with the round and the map. With reduced motion: every third shot of mine, at most 24, none of the others'.
- **Muzzle flash** (`render/muzzle-flash.ts`). Five shapes per gun, never the same twice in a row, at most three frames, side jets for the .50 cal; aimed, when the gun hides its muzzle, wings to both sides and nothing in the sight picture; a point light on the gun and hands, a little smoke after a burst. Other players' guns show the same shapes. With reduced motion it is smaller and darker, one shot in three, without smoke.
- **Sounds.** Every combat sound is a real CC0 recording ([ui.md](ui.md#audio)): gunshots per weapon, handling, knife, impacts, hit confirms (`hitHead` and `hitKill` replace `hit`; a kill beats a headshot, a beacon hit stays `hit`), hurt, death, infect, beacon, knife bounce, stick and pickup. The M.O.A.B. call is an air raid siren and the detonation a dynamite blast. Perk and ready keep the record chime; round start, Patient Zero and the UAV pulse keep the zone bell. Other players hear your shots and your reloads (the server sends `reload { id, weapon, ms }` to everyone else when a reload starts; their client plays it at your avatar, at chest height). Your own reload is heard move by move as you see it (`Clip.cues` in `render/fp-clips.ts`): the gun taken up, magazine out, magazine in, and what closes at the end; the sniper's bolt after a shot too. Cases ring where they first land (at most three at once, none of the links). Weapon swaps, draws, scope and dry fire are heard only by you.
- **HUD.** Survivors see three slot pills (`[1] primary · [2] Pistol · [3] Knife`), a perk track (Hardline, then 1 Sleight, 3 Scavenger, 5 Steady Aim, 7 Specialist lit by the streak, with the streak count and progress to the M.O.A.B.), a perk-unlock toast, and a pulsing gold `M.O.A.B. ready · N Call` badge. A called M.O.A.B. shows a red-amber `☢ M.O.A.B. inbound · 9.3s · caller` banner under the round header for everyone; the detonation flashes the screen white to amber over 2.4 s (a dim amber wash with reduced motion). Score changes pop up beside the crosshair, hits show their direction on a ring around it, and the round summary is a table of the server's per-player stats; see [ui.md](ui.md#infected-hud).
- **Physics & Maps.** Uses `INFECTED_CVARS` (`ZOMBIES_CVARS` run-and-gun profile). Maps (`kind: 'infected'`, `layout: 'open'`): `infected_outpost` ("Outpost"), `infected_terminal` ("Terminal"), and `infected_foundry` ("Foundry").

### Practice range

While there is no round (`waiting` with fewer than 2 active players, and solo offline) the local player can fire, reload, swap, aim and feel the recoil as in a round, against up to 3 stationary target dummies (`PRACTICE_TARGETS`) at map spawns at least 256 units away. Targets have the infected look and a `TARGET` tag, 5 HP, die to a headshot, and come back after 3 s at another spawn. The range is client-only (`apps/web/src/lib/game/infected-practice.ts`): shots are resolved locally with the shared hitboxes and nothing weapon-related is sent to the server. A spent reserve refills, and `4` cycles the primary through `INF_PRESETS`. It closes the moment the grace period starts (the server's spawn and ammo win) and is off while spectating. HUD: [ui.md](ui.md#infected-practice-range).

## Zombie Run

Mode id `zombies` (family `coop`), label "Zombie Run" (the id, map ids, protocol fields and `ZOMBIES_CVARS` keep the old name). Prototype co-op mode (map: `zombies_lowtide`). Server-authoritative online; offline the client runs the same shared `ZombiesGame` locally, so it is playable solo. Code: `packages/shared/src/modes/zombies/` (`weapons.ts`, `hitbox.ts`, `path.ts`, `gates.ts`, `game.ts`, `net.ts`, tests), `apps/server/src/modes/zombies.ts`, client `apps/web/src/lib/game/zombies.ts`, `render/zombies.ts`, `ui/ZombiesHud.svelte`.

### Rules

- **Round flow.** `waiting` (nobody on the map) → `countdown` 8 s (everyone spawns at the start as a survivor and picks a weapon) → `playing` → `ended` (7 s summary in chat and HUD: time, kills, top killer) → next countdown. One player is enough. A round over 15 min is lost.
- **Goal.** The route is split into zones by **gates** (glowing amber barriers). The round is **won** when any survivor reaches the evac zone (the end zone at the pier tip, behind the last gate). It is **lost** when no survivors are left.
- **Gates.** Each gate has an unlock area on its near side (green floor marker). When at least **50 %** of the living survivors stand in it at the same moment (1 of 1, 1 of 2, 2 of 3, 2 of 4, ...), a **30 s** countdown starts (HUD and chat). It is never cancelled: survivors may leave the area. When it ends, the gate's collision is removed and the mesh fades. Only the first closed gate can start counting. Gate state and seconds left are in `modeState.gates`.
- **Checkpoints** (one per zone, before its gate): the first survivor in one heals all survivors to full and refills reserve ammo. Late joiners spawn there as survivors.
- **Survivors** have 5 HP. Each zombie hit takes 1 (300 ms of invulnerability after a hit, no regeneration). Falling into the water costs 1 HP and teleports back to the checkpoint.
- **Turning.** A survivor at 0 HP joins the **zombie side** for the rest of the round: after 3 s they rise at a zombie spawn area as a player-controlled zombie. They have zombie stats: 265 u/s (slowed by hits like AI zombies), 8 HP, the zombie hitboxes (headshot = kill), claws only (melee, 64 reach, 0.9 s between swings, 1 HP per hit on survivors). Killed player-zombies respawn after 4 s. Their kills on survivors count. They cannot pick weapons, trigger checkpoints, gates or the evac. Remote player-zombies are drawn in zombie colours with a green `ZOMBIE · name` tag. Everyone starts the next round as a survivor.

- **Passing a gate.** A living survivor passes the next gate on their own way when the gate is open and their hull is behind it (a 512-deep box on the route's side, `gateFarSide`; a checkpoint or the evac beyond it also counts, for gaps in the packets). `ZmPlayer.zone` counts the gates behind a survivor. A spawn at a checkpoint (late join, fall-out) moves `zone` forward without passing anything, and for 1 s after a teleport nothing is passed. The game reports it as event `pass { id, index }`, which the server uses for coins and does not send.
- **Coins** ([economy.md](economy.md#zombie-run)): passing a gate, the evac (every living survivor who passed the last gate and half of all gates), survivors caught as a player-zombie. `roundStart` when the round starts, `roundEnd` after the end (or when everyone left), `contact` for every survivor caught by a player-zombie.

### Weapons

One weapon per life, picked with **1-4** while the loadout window is open (countdown, and 15 s after a (re)spawn); a map vote keeps 1-4 while it is open. Mouse1 fires (`+attack`), **R reloads** (in Zombie Run only; `!r` restarts the round in solo, online rounds restart by themselves), mouse2 toggles the sniper scope. Damage is in zombie HP (8); **any headshot kills**. Movement speed is the weapon's (CS-style `sv_maxspeed`).

| Key | Weapon | Body hits to kill | Move speed | Fire | Magazine / reserve | Reload | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Light machine gun | 8 | 195 | 80 ms, automatic | 100 / 300 | 4.2 s | 1.6° spread |
| 2 | Pistol | 4 | 240 | 150 ms | 12 / 96 | 1.5 s | 0.5° spread |
| 3 | Knife | 1 | 250 | 450 ms | — | — | 76 reach, 38° cone |
| 4 | Sniper rifle | 1 | 205 | 1.25 s bolt | 5 / 30 | 3.0 s | pierces 3 zombies; scope 40° FOV, no spread scoped (3° unscoped) |

Hits slow a zombie for 0.6 s (×0.6, stacking to ×0.5 and ×0.42) and push it back (pistol 80, LMG 40 u/s).

### AI zombies

- **Bodies.** Each zombie is a player hull moved by the real `playerMove` (gravity, steps, collision with the map and closed gates) at 64 Hz, with its own cvars (no autobhop). Base speed 265 u/s (survivors 195-250). 8 HP. Hitboxes (`hitbox.ts`): a vertical cylinder (radius 13, 0-54) and a head sphere (radius 7.5, 7.5 forward along the yaw, 65 up) matching the hunched model.
- **Steering.** Target = nearest living survivor (re-picked every 8 ticks). If it is close, or in line of sight within 1100 units, the zombie runs straight at it; otherwise it follows the map's waypoint route (`MapDef.zombies.path`) towards the target's route progress with a 160-unit look-ahead. Separation from nearby zombies (no zombie-zombie collision). Blocked while moving: jump. Zombies at a closed gate wait there; others that make no progress for 6 s are removed (the spawner refills).
- **Attacks.** Within 50 units: 350 ms wind-up (shown as a lean and glow), then 1 hit if still within 65; 0.9 s cooldown.
- **Spawner.** Endless while the round runs: one zombie per interval as long as fewer than the cap are alive (no initial group and no total per zone; the first one comes 1.5 s after the round starts). It uses spawn areas (`MapDef.zombies.spawnZones`) feeding route nodes from 2 behind to 3 ahead of the front survivor, at least 700 and at most 3200 units from survivors, and never areas behind a closed gate. Zombies 1600 route units behind the last survivor and 1200 from everyone despawn.
- **Scaling.** Interval and cap depend on `n`, the **living survivors**. Dead and turned players, spectators and others connected do not count. The number is read again for every spawn, so a survivor who turns, joins or leaves changes both within one interval (at most 1.5 s). When the cap drops below the number alive, nothing is removed; the spawner waits until kills bring it below the new cap. Zombie HP, damage and speed do not depend on `n`, and the gate rule is always 50 % of the living survivors. The formulas are `zmSpawnInterval` and `zmZombieCap` in `game.ts`:
  - interval = `max(50 ms, 1500 ms / n^0.85 · (1 − 0.35·progress))`
  - cap = `min(96, round(18 · √n))`

  | Living survivors | Alive cap | Spawns per minute (start of the route to its end) | Per survivor and minute (start) |
  | --- | --- | --- | --- |
  | 1 | 18 | 40 to 62 | 40 |
  | 2 | 25 | 72 to 111 | 36 |
  | 4 | 36 | 130 to 200 | 33 |
  | 8 | 51 | 234 to 360 | 29 |
  | 16 | 72 | 422 to 650 | 26 |
  | 32 | 96 | 761 to 1171 | 24 |
- **Cost.** Measured on the real server (Node 24, desktop CPU, simulated WebSocket clients, zombies held at the alive cap and all chasing): the 32 Hz mode tick (2 steps of the 64 Hz simulation, encoding and sending included) takes on average 0.4 ms with 1 survivor and 18 zombies, 1.2 ms with 8 and 51, 1.9 ms with 16 and 72, and 3.5 ms (p99 10 ms) with 32 and 96, of a 31 ms budget (about 18 % of one core for the whole server). `BIN_ZOMBIES` is 34 kB/s per client at 96 zombies (6.6 kB/s at 18).

### Netcode

- **Zombies:** `BIN_ZOMBIES` (type 4) every mode tick (32 Hz), droppable under backlog: `u8 4, u8 version 1, u32 sim tick, u8 count`, then 11 bytes per zombie (`u16 id`, `i16 x·2, y·2, z·2`, `u8 yaw·256/360`, `u8 flags` (attacking, hit, slowed, on ground), `u8 hp·255`). Clients interpolate them 100 ms in the past like remote players (`net/zombie-interp.ts`).
- **Shots:** C→S `fire { weapon, origin (eye), dir (unit), tick }`, `reload {}`, `loadout { weapon }`. The client predicts fire rate, ammo and reloads and draws tracers and the muzzle flash at once. The server checks: alive, weapon is the player's, fire interval ≥ 75 % of the weapon's (jitter tolerance; reloads 85 %), ammo, finite values, a unit direction, and an origin within 80 units of the last state's eye. Rejected shots answer with an `ammo` resync. **Lag compensation:** `tick` is the interpolated zombie sim tick the shooter was looking at; the server bounds the tick by the shooter's RTT and interpolation budget within the 400 ms history. It tests AI poses by sim tick and interpolates player-zombie poses from the player snapshots sent around that tick's server time. World geometry (and closed gates) stop bullets.
- **Events:** S→C `zm { ev }` with `ev.e` = `phase`, `spawn` (teleport/respawn, team and hp, to that player), `hit` (hit marker, to the shooter), `kill` (kill feed; `pid` for player-zombies), `shot` (others' tracers), `hurt`, `zhurt` (player-zombie slow and knockback, to that player), `down` (turned), `checkpoint`, `gate`, `ammo` (to that player), `end`. `modeState { mode: 'zombies', phase, round, timeLeft, elapsed, checkpoint, checkpoints, progress, zombies, kills, gates[], players[{ id, team, hp, alive, kills, deaths, weapon }] }` on change (≤ 4 Hz) and every second. Player health and teams are server-authoritative; positions stay client-authoritative as in the other modes.
- **Physics.** `ZOMBIES_CVARS` = surf profile with `sv_airaccelerate 30` and `sv_enablebunnyhopping 0` (CS2 cap: 286 u/s on each jump), autobhop on: run-and-gun.

### Known gaps (prototype)

- Gunshots, knife, reload, hit and hurt share the Infected recordings (`ZOMBIES_SOUNDS` in `apps/web/src/lib/audio/combat.ts`, played through `GameAudio.zombies`) and follow the same distance and voice rules ([ui.md](ui.md#audio)). The zombie groan has no recording yet; the checkpoint and gates keep the zone bell.
- Player-zombies pass through survivors and AI zombies. Their speed and slows are applied client-side.
- Zombie navigation is a single waypoint route; zombies spawned off it walk straight to it.
- Viewmodels are code-built low-poly models (`render/viewmodels.ts`): each gun has its type's parts and is held by gloved hands, the knife by a fist. The guns and the knife are replaced by their model files once those have loaded, as in [Infected](#infected) (the Weapon models bullet). In zombies the viewmodel moves with the recoil kick, the shots, the reloads and the sniper's bolt of Infected (a code-built gun drops out of the way while it is reloaded) and the knife swing, with casings and flashes; sway, the draw, aiming and the landing dip are Infected only.

## Hide and seek

Mode id `hns` (family `hns`), label "Hide and Seek". Built like the CS:GO community hide and seek servers, with the "infection" twist the owner asked for: a hider knifed by a seeker becomes a seeker. Server-authoritative: the shared `HnsGame` (`packages/shared/src/modes/hns.ts`) runs in `apps/server/src/modes/hns.ts`; the client (`apps/web/src/lib/game/hns.ts`, `hns-view.ts`, `ui/HnsHud.svelte`) only displays the result and sends knife swings. Maps: `kind: 'hns'` with `MapDef.hns` ([maps.md](maps.md)).

### Rules

| Phase | Length | What happens |
| --- | --- | --- |
| `waiting` | while < 2 players | Free roam as a hider, HUD "Waiting for players — needs 2+". Offline (solo) the same, with "(offline: free roam)". No bots. |
| `starting` | 5 s | Countdown once 2 players are in (first round only). |
| `hiding` | 30 s (`HNS_HIDE_SECS`, env `HNS_HIDE_SECS`) | Seekers are teleported to a seeker spawn, **frozen and blindfolded** (black screen with the release countdown). Hiders are teleported to distinct, shuffled hider spawns and spread out. |
| `seeking` | 4:00 (`HNS_SEEK_SECS`, env `HNS_SEEK_SECS`) | Seekers are released ("Ready or not, here they come!", gavel sound) and hunt with knives. Warnings at 60, 30 and 10 s left; "X is the last hider!" when one is left. |
| `ended` | 8 s | Summary in chat and HUD (winner, survivors, top seeker by finds), then the next round's hiding phase starts with re-picked seekers. |

- **Seekers.** 1 seeker, 2 from 8 players (`HNS_TWO_SEEKER_PLAYERS`, the same split tag uses). At each round start the seekers are picked among the players who have not *started* a round as seeker for the longest (never first), randomly among ties, so the role rotates. Seekers get the knife (Mouse1); hiders have no weapon.
- **Knife.** Reach 64 units from the eye to the target's hull surface, 30° aim cone (×1.6 within 40 units), one swing per 0.5 s, one hit kills (`HNS_KNIFE`). The client sends `knife { origin, dir }`; the server checks: seeker, seeking phase, not frozen, finite values, a unit direction, origin within 80 units of the seeker's last eye, swing interval ≥ 75 % of 0.5 s, and line of sight (world trace; `solid: false` brushes do not block). **Lag compensation:** every state packet is stored with its arrival time (500 ms history); a swing is tested against each hider at `now − min(400, ping + 116) ms` (the seeker's RTT plus the 100 ms client interpolation delay and half a snapshot interval) and at their latest position; either counts, the closest hit wins.
- **Found.** The hider becomes a seeker at once, is teleported to a seeker spawn and is frozen there for 3 s (`HNS_FOUND_FREEZE_SECS`; HUD "You were found by X — you are now a seeker", kill feed "X found Y"). Respawning at the seeker spawn (as CS:GO servers moved killed T to the CT side) instead of in place means a found hider cannot instantly knife the hider standing next to them.
- **Win.** Seekers win the moment no hiders are left (found, or the last hiders left the server). Hiders win when the seeking clock runs out with at least one hider left. Scores: finds (hiders knifed) and seconds survived as a hider in the seeking phase; both reset each round.
- **Late joiners** during hiding or seeking join as seekers (frozen with the others while hiding): a fresh hider spawn could be next to a seeker, and joining as seeker cannot be used to scout. Between rounds they are hiders.
- **Disconnects.** A leaving player is removed from the round. If every seeker leaves, a random hider becomes the seeker (teleported, frozen 3 s while seeking). Dropping below 2 players cancels the round and goes back to waiting.
- **Freeze is server-enforced.** A frozen player whose position is more than 48 units from their freeze spawn is teleported back (`spawn` event, at most every 0.5 s); the client also skips movement while frozen.
- **Cash bag.** Once per round, halfway through the seeking phase (`HNS_BAG_AT`), with 3 or more active players, a bag with 4–10 coins appears at `MapDef.hns.cashBag`. Announced in chat and on the HUD with its place; the first living hider to touch it gets it, seekers cannot. It stays until taken or the round ends ("Nobody took the cash bag."); late joiners get it with `modeState`. All payouts of this mode: [economy.md](economy.md#hide-and-seek).
- **`!r` / `!back`** respawn (hiders at a hider spawn, seekers at a seeker spawn) only outside a round. Fall-out teleport zones respawn by role; teleport zones with `dest` move the player to that point (secret passages).
- **Name tags.** Only within 600 units and in line of sight (`HNS_NAMETAG_RANGE`); seekers never see hiders' tags (no wallhack through tags), and during a round spectators do not either, since they come back as seekers. Seekers are drawn red with a red `SEEKER · name` tag.
- **Physics.** `HNS_CVARS` = surf profile (CS2 accelerate 6.5, friction 5.2, 250 run speed, legacy full-height jump), autobhop on, and the same soft bhop cap as Zombie Run and Infected: `sv_enablebunnyhopping 0` (each jump trims the speed to 286 u/s) with `sv_airaccelerate 30`. Strafing gains some back in the air: about 300 u/s on average, up to about 340. The server logs state packets above 600 u/s (`HNS_SPEED_LIMIT`) and ignores that player's knife swings for 1 s after one.
- **Messages.** C→S `knife { origin, dir }`. S→C `hns { ev }` with `ev.e` = `spawn` (teleport + freeze, to that player only), `swing` (to the others), `waiting`, `starting`, `roundStart`, `release`, `found`, `newSeeker`, `lastHider`, `warn`, `bag { pos, place }`, `bagTaken { by, coins, paid }`, `end`. `modeState { mode: 'hns', phase, round, timeLeft, seekers[], hiders[], winner, players[{ id, role, finds, survived, frozen }], bag? }` (`bag`: `pending { secs }`, `out { pos, place }`, `taken { by, coins }` or null) on every change and once a second. Scoreboard rows: `status` Hider/Seeker, `kills` = finds, `score` = seconds survived.

### Why these numbers (research)

CS:GO hide and seek was never an official mode; every community server ran its own plugin and config, so these are the common conventions rather than one standard:

- **Freeze and blind the seekers at round start.** The original SourceMod plugin's `sm_hns_freezects` ("Should CTs get freezed and blinded on spawn?", default on): [AlliedModders: SM Hide and Seek](https://forums.alliedmods.net/showthread.php?p=1162319). The CS2 HNS plugin ChaseMod freezes the seekers for `ctStartFreezeTime` 15 s by default: [ChaseMod](https://github.com/ipsvn/ChaseMod) ([config](https://github.com/ipsvn/ChaseMod/blob/master/ChaseModConfig.cs)). A Workshop HNS map gives hiders one minute to hide: [Steam Workshop: Hide and Seek map](https://steamcommunity.com/sharedfiles/filedetails/?id=2445282334). We use 30 s (owner's choice): long enough to reach a nearby hiding spot, short enough to keep rounds moving.
- **Round length.** That Workshop map gives seekers 10 minutes, hosting guides quote 8-10 minute matches ([Apex Hosting HNS guide](https://apexminecrafthosting.com/guides/csgo/setup-and-play-a-hide-seek-csgo-server/)). With conversion (seekers multiply) rounds end faster, so 4:00 of seeking keeps one map (15 min) at 2-3 rounds.
- **Knife-only seekers, unarmed hiders, seekers chosen in turns.** ChaseMod's knife damage/cooldown settings and its team switching on a seeker win ([ChaseMod](https://github.com/ipsvn/ChaseMod)); we rotate seekers by "sought least recently" instead of team swaps.
- **Last-hider events.** The Workshop map reveals everyone at one minute left or one hider left; we only announce the last hider (and 60/30/10 s warnings), because a reveal would make the bhop cap the only defence.
- **Bhop cap 300** is the owner's rule.

### Known gaps

- Positions are client-authoritative as in every mode: snapshots still carry every player's position, so a modified client could show hiders through walls. Server-side visibility culling is not done.
- Sounds are real CC0 recordings (CREDITS.md): the knife swing (your own, or another seeker's within 1024 units, quieter with distance), the knife hit (for the finder and the found hider), and the existing gavel for the seeker release. The cash bag's appearance reuses the zone bell; no coin recording is sourced, so the pickup is silent.
- No spectating while found (found hiders play on as seekers); spectating works as in every mode.
- Map votes give hns no reserved slot (`VOTE_MAP_SLOTS` covers surf/bhop/tag/zombies); hns maps fill free slots like any map.
